# Bee → Muse → reviewed daily repository

Bee supplies completed transcripts; its own app may provide notes and briefs, but Lima's current delivery connector imports transcript text. Lima does not claim that Bee notes/briefs or raw audio automatically arrive through this connector.

Muse Spark 1.3 organizes selected sources and drafts email, personal calendar, text and contact proposals. A separate schema-constrained Muse pass writes the daily Notion repository note from up to 80 selected/current evidence records, with IDs linking back to exact quotes. Pending interpretations cannot be labeled reviewed; learning labeled reviewed must cite current accepted reference evidence. The note appends locally recorded follow-up destinations, draft excerpts and actual receipt states. It does not invent delivery receipts. No unsupported output type is required merely to fill a daily quota.

Process my day / Process this meeting (pipeline version 4) prepares the repository draft after a complete first interpretation and reconciliation pass. A failed section leaves a partial job and holds the repository note. Daily review also offers Draft / refresh Muse daily note with explicit Meta consent. Reviewing project claims, editing follow-ups, dismissing an action or receiving a delivery receipt can require fresh preparation. Older drafts and user amendments are preserved. A note's approval/publication gate checks both project evidence and the follow-up snapshot.

Notion is the reviewed daily repository across destinations. Gmail/Calendar/Google Contacts remain actual action destinations. The reviewed Notion note is a one-way snapshot, not automatic two-way synchronization or a live remote execution console. Refresh and separately approve it after actions change. Publishing a note cannot execute an instruction inside it. Existing dedicated Notion approval, destination checks and duplicate/unknown-write guards are reused.

Text messages are editable and copyable only; no SMS or WhatsApp sending provider is connected. Contact proposals retain only literal names, email addresses and international phone numbers in their source quote. Missing fields stay blank. Contact creation needs the optional Google Contacts scope and People API; it checks existing names/email/phones, holds potential duplicates, binds approval to account/content/version/context, reads back a successful creation and freezes uncertain writes. No automatic contact merges, updates or deletes are enabled.

Bounded Muse calls now request explicit low reasoning effort to leave room for structured output within the 8,192-token ceiling. The original synthetic multi-output run hit the output limit; the resumed run completed after this setting change. Both artifacts are retained.
