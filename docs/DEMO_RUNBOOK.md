# Three-minute Lima demo

## Reliable offline showcase

```powershell
python -m lima_next.demo --showcase --db demo-data/showcase.sqlite3
python -m lima_next serve --db demo-data/showcase.sqlite3 --port 8766
```

Open http://127.0.0.1:8766, then Open daily review. Use a new database name to repeat; an existing database is never reset. The standalone showcase needs no account, recording, model key or Internet connection. Bee and nightly workers begin disabled. Google/Notion are disconnected.

This mode replays captured, actual Muse Spark 1.3 output on a scripted synthetic meeting. The earlier reviewed decision is a manually seeded fixture. Four follow-up types and the daily repository draft are recorded model outputs; local IDs are remapped. The UI shows replay provenance. Nothing is presented as a fresh model call or delivered message. The original evaluation hit an output limit; its explicit-low-reasoning resumed run completed. External account checks and field outcomes are separate evidence.

## Fresh Muse run

```powershell
python -m lima_next.demo --day-workflow --db demo-data/fresh-run.sqlite3
python -m lima_next serve --db demo-data/fresh-run.sqlite3 --port 8766
```

Set MODEL_API_KEY locally before launch. Inspect the scripted source snapshot, consent and Process my day. This mode contains only source material and a seeded prior decision; model output is generated by the new run. The source requests an email, a personal time block, contact capture and a text draft. No output type is guaranteed: errors, abstentions and missing information remain visible. Do not replace a failure with the replay while claiming the result was live.

For the five smaller model checks:

```powershell
python -m lima_next.demo --db demo-data/meta-check.sqlite3 --evaluate-meta --consent-synthetic-meta --output demo-data/meta-results.json
```

## Three-minute story

- 0:00–0:20: lived problem and scope. State that this walkthrough uses scripted data and recorded Muse output.
- 0:20–0:40: Bee transcript/source evidence and the earlier reviewed project decision.
- 0:40–1:00: open the completed day review; four follow-ups and the Muse daily repository draft.
- 1:00–1:20: email body, explicit recipient, original quote and separate draft/send previews.
- 1:20–1:40: contact proposal. Literal details only; duplicate checks and optional Google permission. Live contact write remains deferred.
- 1:40–1:55: text draft. Copy into a messaging app; no SMS provider or automatic sending.
- 1:55–2:15: personal calendar proposal, exact date/time and own-calendar selection. Approval and read-back are separate from drafting.
- 2:15–2:40: Muse's Notion daily review. Show reviewed context, proposed items and destination/status snapshot; publishing the note does not execute its instructions.
- 2:40–3:00: approval policy, specific verified account checks and honest boundaries. Tuesday's field measurement is still prospective until it happens.

The generated narrated MP4 is a recorded walkthrough with a generic synthetic voice, not a live screen recording or the builder's voice. Review its pacing and update the field-results ending after Tuesday. The final repository and video links still need to be entered into the submission form.

## Real delivery demonstrations

Connections are per workspace. Use a dedicated, explicitly approved synthetic recipient/event/note and configure its destination separately. Never attach production credentials or private databases to the public demo. Do not send to example.com or a fictional phone number. The offline showcase contains no real account writes and does not fabricate delivery receipts.
